## 0. 왜 이 감사를 하는가 — 정호님 지적

> *"계속 기존 문제를 막기 위해 무언가를 추가하고 덧대면 서로 충돌되는 문제가 계속 생기고, 읽어야 할 데이터도 많아지고 복잡해지는 거 아니야?"*
> *"근본적으로 기존의 어떤 규칙이 잘못된 결과를 낸다면 그 원인을 파악하고 제거하는 게 더 깔끔한 방법 아니야?"*

**원칙: 새 규칙을 덧대지 않는다. 사고를 유발하는 기존 규칙을 찾아 도려낸다.**
이 원칙에 따라 2026-08-19에 **새 파일 `script-rules.md`를 만들었다가 스스로 삭제하고 공통 원본 3곳을 정정**했다(§1).

## 2. 🔴 이미 발견한 의심 지점 (감사 시작점 — 여기부터 확인)

### 2-1. 게이트가 사실상 무시되고 있다

**실측(2026-08-19)**: `check_tone.py`를 전체 대본에 돌리니 **탐정경제학 90편 중 과반이 「숫자 밀도 상한 10.0」 FAIL**인데 전부 발행됐다.

- 게이트가 FAIL인데 발행됐다면 ① 대본이 게이트 도입 전에 쓰였거나 ② 검수에서 무시됐거나 ③ **상한 10.0이 탐정에도 안 맞거나**
- `script-reviewer.md:112`는 *"상한 항목 중 하나라도 실패 → 치명적. **등급 강등 금지**"* 라고 적고 있다. **규칙과 실태가 어긋난다**
- 확인법: 대본 작성일과 `check_tone.py` 도입일(2026-08-10경) 대조 → 도입 후 대본만 골라 재판정

### 2-2. WARN이 차단을 못 해 사고가 났다 (같은 구조가 더 있는지)

08-16은 **비유 소재 4.6 / 상한 3.0으로 WARN이 떴는데** 검수자가 *"확장 비유 하나를 깊게 판 결과이므로 위반 없음"* 으로 통과시켰다. 그 비유가 개념을 잠식해 사고가 났다.

- `_WATCH`(WARN)로만 둔 항목이 또 있는지, 그게 사고 경로인지 확인
- 반대로 **FAIL인데 실제로는 오탐이라 매번 무시되는 항목**도 찾는다 (2-1과 짝)

### 2-3. 「폐기·철회」로 표시됐는데 다른 파일에 살아 있는 규칙

`tone-guide.md`에 *"❌ 옛 규칙 — … (2026-08-10 폐기)"* 같은 표시가 여러 개 있다.
**폐기 표시는 그 파일에만 있고, 같은 지시가 다른 파일에 그대로 남아 있을 수 있다.**

- 확인법: `grep -rn "폐기\|철회\|옛 규칙\|더 이상 쓰지" prompts/ .claude/` → 각 폐기 항목의 **핵심 문구를 repo 전체에서 재검색**

### 2-4. 같은 지표가 파일마다 다른 수치

- `check_tone.py` 숫자 밀도 상한 10.0 ↔ `script-reviewer.md:115` "1,000자당 10개 초과" ↔ `script-review-checklist.md` 어딘가
- 방구석은 `_CHANNEL_BANDS`로 34.0인데 **문서에는 여전히 10.0으로 적힌 곳이 있을 수 있다**
- 확인법: 숫자가 들어간 규칙(밀도·1인칭·반문·용어·세이프존 3/8·9장)을 repo 전체 grep해 **불일치 목록** 작성

### 2-5. 원본이 둘 이상인 규칙 (단일 출처 원칙 위반)

[[feedback_rule_single_source]]가 "원본 1곳 + 나머지는 참조"인데 실제로 지켜지는지.
특히 **썸네일 세이프존·9장 배분·인물 크기**는 "유일한 원본"이라 명시된 곳이 여러 파일에 흩어져 있다.

### 2-6. 채널별 근거가 공통 규칙에 박혀 있는 경우 (오늘 3건 확인)

**오늘 찾은 것만 3건이다. 더 있을 가능성이 높다.**

| 규칙 | 근거 | 문제 |
|---|---|---|
| 숫자 밀도 상한 10.0 | *"우리는 시니어 타겟이고 203k 히트작이 4.6"* | 탐정 근거. 방구석 벤치는 23~33 |
| 반문 하한 3.5 | *"벤치마크가 60초에 한 번꼴로 던진다"*(203k 잠수함편 7.9) | 탐정 근거. 방구석 벤치 히트는 1.4~3.7이고 **질문이 많은 쪽이 죽는다** |
| 실사형 썸네일 "발광·일러스트 금지" | 축 D(자영업) 레퍼 2장 | A-1·A-2 최강 레퍼가 정확히 그 스타일 |

- 확인법: `prompts/` 안에서 **"실측·근거·왜냐하면"이 붙은 수치 규칙**을 전부 뽑아, 그 근거가 **어느 채널 데이터인지** 표시. 한쪽 채널 근거면 `_CHANNEL_BANDS`나 채널 config로 내린다

## 3. 감사 방법 — 정독 대신 탐지 grep

컨텍스트를 아끼려면 전문 정독을 하지 않는다. 아래로 **의심 지점만 추린 뒤** 그 부분만 읽는다.

```bash
# ① 폐기 표시 수집 → 각 문구를 repo 전체 재검색
grep -rn "폐기\|철회\|옛 규칙\|더 이상\|이제 쓰지" --include="*.md" prompts/ .claude/

# ② 수치 규칙 전수 → 불일치 탐지
grep -rnE "1,?000자당|상한|하한|이하|이상|초과|미만" --include="*.md" prompts/ .claude/ | grep -E "[0-9]"

# ③ "유일한 원본" 선언 → 중복 여부
grep -rn "유일한 원본\|여기에 다시 적지\|원본이다" --include="*.md" prompts/ .claude/ channels/

# ④ 금지/필수 충돌 후보
grep -rn "⛔\|금지\|절대\|반드시\|필수" --include="*.md" prompts/ | wc -l
```

**대상 범위**: `prompts/`(15개) · `.claude/agents/`(8개) · `.claude/skills/`(4개) · `channels/*/config/`
⛔ `prompts/_archive/`·`notes/`·`_refs/`는 제외 (과거 기록이라 충돌 대상 아님)

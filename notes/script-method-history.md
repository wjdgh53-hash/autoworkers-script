# 대본 작성 방식 변천사

> **방식을 바꿀 때마다 여기에 한 항목씩 추가한다.** 바꾸기 전에 규칙 파일을
> `prompts/_archive/{날짜}-{이름}/`에 복사해 두고, 그 경로를 아래 표에 적는다.
>
> **왜 필요한가:** 2026-08-10, 정호님이 지적하셨다 — "지금까지 몇 번 수정을 했는데,
> 그전 방식들 중에 좋은 점이 있었는지 없는지 **분석조차 불가능하다.** 그냥 수정해 버리면."
> 실제로 그 시점에 미커밋 파일이 55개였고, 현재 방식은 git 어디에도 없었다.
> 규칙 파일만 보존하면 되고, 프로젝트 산출물은 대상이 아니다.

## v2 → v3 (2026-08-10)

**보존 위치:** [`prompts/_archive/2026-08-10-pre-skeleton/`](../prompts/_archive/2026-08-10-pre-skeleton/)
(파일명의 `__`는 원래 경로의 `/`다. 예: `prompts__tone-guide.md` → `prompts/tone-guide.md`)

**계기:** 정호님 지적 — "우리 대본이 너무 비슷한 예시를 많이 든다. 그래서 오히려 부자연스럽다."

**실측 근거** (1,000자당, 벤치마크 3편 vs 우리 3편):

| 지표 | 레퍼 | 우리 (v2) |
|---|---|---|
| 일상 비유 | 0.4 / 0.2 / 3.5 | 4.1 / 4.0 / 3.4 |
| 1인칭 리액션 | 0.5 / 0.2 / 0.2 | 3.2 / 2.8 / 3.7 |
| 숫자 밀도 | 15.7 / 7.0 / 9.3 | 5.1 / 2.0 / 3.5 |

**바꾼 것:** 개편안 전문은 [`script-overhaul.md`](script-overhaul.md) 참조.

**v2에서 버린 것 중, 되살릴 만한 것이 있는지 나중에 볼 목록:**

- 개념 3중 설명 (정의 → 일상 사물 → 생활 비유, 분량 8~10%) — 시니어 타겟에는 유효했을 수 있다
- 비유 하한 8회 — 과했지만, 0으로 가면 대본이 차가워질 수 있다 (v3는 상한 1.5로 남김)
- 1인칭 8~12회 분산 — 온기의 원천이었다 (v3는 1.0 수준으로 축소)
- "쉽게 풀어주기" 하한 8회 — v3에서 폐기했다. 레퍼는 0.0~0.1이지만 우리 타겟은 레퍼보다 고령이다

> 위 4개는 **레퍼 대비 과잉이라 줄인 것이지, 틀렸다고 판정한 게 아니다.**
> v3 대본이 "차갑다"는 반응이 나오면 여기부터 되돌린다.

## 다음 방식 변경 시 절차

1. `prompts/_archive/{YYYY-MM-DD}-{이름}/`에 바꿀 규칙 파일을 복사한다
2. 이 문서 연표에 항목을 추가한다 — **무엇을·왜·그때 성과가 어땠는지**
3. "버린 것 중 되살릴 만한 것" 목록을 남긴다. 이게 없으면 되돌릴 수가 없다
4. 가능하면 git 커밋을 함께 남긴다 (커밋은 정호님 승인 후)

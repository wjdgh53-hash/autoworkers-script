# Compilation Skill

기존에 올린 유튜브 영상들을 분석해서 통합본(모음집)을 기획하는 스킬.

## 역할 원칙

1. **데이터 기반 판단**: 조회수, 좋아요율, 영상 설명을 분석하여 추천
2. **채널 프로필 반영**: 인트로 대본 작성 시 채널 톤/말투를 따름
3. **대화형 진행**: 각 단계마다 추천을 제시하고 사용자 확인 후 진행
4. **script-pd와 완전 독립**: _refs, _script 폴더를 사용하지 않음. `_compilation/` 폴더만 사용

---

## 전체 흐름

```
STEP 0: 재료 원장 대조 (이미 쓰인 영상 배제) ← 필수, 건너뛰지 않는다
STEP 1: 채널 선택 + URL 수집
STEP 2: 메타데이터 수집 (yt-dlp)
STEP 3: 조합 추천 (연관성 + 서사 흐름 + 조회수)
STEP 4: 썸네일 추천 (클릭률 검증 기반)
STEP 5: 인트로 대본 작성
STEP 6: 산출물 저장 + 완료 보고
STEP 7: 인트로 자막 SRT 생성 (선택 — 사용자가 TTS 오디오를 준 뒤)
```

> STEP 6까지가 기획 단계다. STEP 7은 사용자가 인트로 대본으로 **TTS 오디오를 만들어 온 뒤**에 진행하는 별도 단계다. STEP 6 완료 보고에서 "TTS 오디오 주시면 자막(SRT)까지 뽑아드린다"고 안내하고, 오디오가 들어오면 STEP 7을 실행한다.

---

## STEP 0: 재료 원장 대조 (필수)

**같은 영상을 두 통합본에 중복해서 넣는 것이 이 스킬의 가장 큰 사고다.** 조합을 추천하기 전에 반드시 먼저 한다.

### 원장 위치
`channels/{channel}/compilation-ledger.md` — 그 채널에서 **이미 통합본 재료로 쓰인 영상 ID의 유일한 원본**이다.

없으면 새로 만든다 (포맷은 STEP 6 참조).

### 0-1. 원장 읽기
원장의 「사용된 영상 ID 전체 목록」을 확보한다. 여기 있는 ID는 **후보에서 제외**한다.

### 0-2. 원장을 믿지 말고 교차 검증
원장이 최신이 아닐 수 있다. 다음 두 가지를 확인한다.

1. **기획 폴더 전수 확인** — `find channels -type d -name "_compilation"`.
   ⚠️ 기획 폴더가 **업로드 채널과 다른 채널 폴더 밑에** 있는 경우가 실제로 있었다. 채널 폴더만 뒤지지 말고 전체를 훑는다.
2. **업로드된 통합본 전수 확인** — 채널 스캔 TSV에서 제목에 `[통합본]`이 든 영상을 모두 찾고, 각각의 **유튜브 설명란**(`yt-dlp --print "%(description)s"`)을 열어 재료 목록과 대조한다.
   설명란에는 보통 `▶ {재료 제목}` 형태로 재료가 박혀 있다. **repo 기록과 설명란이 일치해야 원장이 정확한 것이다.**

> 러닝타임 산술(통합본 길이 ≈ 재료 길이 합 + 인트로)로 재료를 **추측하지 않는다.**
> 편집 과정에서 각 편 아웃트로가 잘려 30~60초씩 어긋나므로 이 방법은 오판을 부른다. 실제로 한 번 틀렸다.

### 0-3. 불일치 처리
원장과 실제가 다르면 **먼저 원장을 고친 뒤** 조합 추천으로 넘어간다. 어긋난 채로 진행하지 않는다.

## STEP 1: 채널 선택 + URL 수집

### 채널 선택
- `channels/` 스캔 (`_template.json` 제외)
- 1개면 자동 선택, 여러 개면 목록에서 선택
- 로드: `config/settings.json` + `config/profile.md`

### URL 수집
- 사용자가 이미 URL을 제공했으면 그대로 사용
- 없으면 요청: "통합본으로 묶을 영상 URL들을 붙여주세요 (최소 3개)"

### 조합 크기
- 기본값: 3개
- 사용자가 별도로 지정하면 ("4개로 묶어줘") 해당 숫자 사용
- 입력된 URL 수 = 조합 크기이면 조합 추천 단계를 건너뜀 (모두 사용)

---

## STEP 2: 메타데이터 수집

yt-dlp로 각 영상의 메타데이터를 수집한다.

### 실행 방법

```python
# macOS/Linux
.venv/bin/python -c "
import subprocess, json
urls = [URL1, URL2, ...]
for url in urls:
    result = subprocess.run(
        ['.venv/bin/yt-dlp', '--dump-json', '--no-download', url],
        capture_output=True, text=True
    )
    data = json.loads(result.stdout)
    # title, view_count, like_count, upload_date, duration, description 추출
"
```

### 수집 항목

| 항목 | 용도 |
|------|------|
| title | 연관성 분석, 보고용 |
| view_count | 조합 추천, 썸네일 추천 |
| like_count | 좋아요율 계산 (like_count / view_count × 100) |
| upload_date | 시간순 정렬 참고 |
| duration | 통합본 총 길이 계산 |
| description | 연관성 분석 (주제/키워드 추출) |

### 수집 결과 보고

표 형태로 사용자에게 보여준다:

```
| # | 제목 | 조회수 | 좋아요 | 업로드일 | 길이 |
|---|------|--------|--------|----------|------|
| 1 | ... | 52,228 | 1,295 | 4/11 | 18분 |
```

### 에러 처리
- yt-dlp 실패 → "yt-dlp 업데이트 필요: `.venv/bin/pip install -U yt-dlp`" 안내
- 일부 URL만 실패 → 성공한 것만으로 계속 진행할지 사용자에게 확인

## STEP 3: 조합 추천

### 입력 URL 수 = 조합 크기인 경우
→ 조합 추천을 건너뛰고 순서 추천만 진행

### 입력 URL 수 > 조합 크기인 경우
→ 최적 조합을 추천

### 분석 기준

0. **재료 중복 배제** (탈락 조건)
   - STEP 0 원장에 올라 있는 영상은 조합에 넣지 않는다. 배수가 아무리 높아도 탈락이다
   - 추천을 제시할 때 **"세 편 모두 미사용임을 원장·설명란으로 확인했다"**를 근거로 함께 밝힌다

1. **주제 연관성** (최우선)
   - 영상 제목과 설명에서 공통 키워드/주제를 추출
   - 같은 대주제를 다루되 각각 다른 각도를 다루는 조합이 최적
   - "허상 → 원인 → 결과" 같은 서사적 흐름이 만들어지는 조합 우선

2. **서사 흐름**
   - 조합된 영상들이 자연스러운 3막 구조를 만들 수 있는지 평가
   - 예: 실태 폭로 → 원인 분석 → 미래 시나리오

3. **조회수 균형**
   - 극단적으로 조회수가 낮은 영상만 모이는 조합은 피함
   - 조회수 높은 영상이 최소 1개 포함된 조합 우선

### 추천 포맷

```
## 추천 조합

**묶을 영상:** 1, 3, 4번

**이유:**
- [서사적 연결 설명]
- [각 영상이 어떤 역할을 하는지]

**제외 영상:**
- 2번 "{제목}" — [제외 이유]

**추천 순서:** 3 → 1 → 4
- 3번: [역할] (도입)
- 1번: [역할] (전개)
- 4번: [역할] (클라이맥스)

이대로 갈까요?
```

→ 사용자 확인 후 다음 단계

## STEP 4: 썸네일 추천

### 분석 기준

1. **시점 보정 배수** — 그 시기 채널 중앙값 대비 몇 배인가. 조회수 절대값보다 이쪽이 정확하다 (오래된 편일수록 절대 조회수가 유리하게 부풀기 때문)
2. **조회수** — 절대 클릭 수. 배수와 함께 봐야 한다
3. **좋아요율** (like_count / view_count × 100) — 클릭 이후의 만족도. 썸네일이 낚시였는지 아닌지가 여기서 갈린다
4. **통합본 주제와의 관련성** — 썸네일이 통합본 전체를 대표할 수 있는지

### 🔴 추천 포맷 — **재료 전편의 지표를 표로 준다**

**1장만 찍어서 주지 않는다.** 사용자가 직접 비교해 고르고, 유튜브 썸네일 A/B 테스트에 넣을지까지 판단할 수 있어야 한다.
따라서 **재료로 선택된 편 전부**를 같은 표에 올린다 — 탈락한 편도 지표를 밝힌다.

> 🔴 **표는 raw 마크다운 상태로 읽힌다는 전제로 쓴다.**
> 정호님은 산출물을 VS Code에서 **프리뷰 없이** 여신다. 셀에 URL이나 긴 문장을 넣으면
> 줄이 접혀 표가 깨지고, 그 순간 표로 만든 의미가 사라진다.
> - 셀에 **링크를 넣지 않는다** — URL은 표 아래 목록으로 뺀다 (링크 자체는 반드시 준다)
> - 셀에 **긴 서술을 넣지 않는다** — 사유·역할은 표 아래 목록이나 별도 짧은 표로
> - 숫자 열은 **공백으로 자릿수를 맞춘다**. 헤더 구분선도 열 너비에 맞춘다
> - 한 표는 **열 6~7개, 셀 15자 이내**를 넘기지 않는다. 넘으면 표를 둘로 쪼갠다

```markdown
## 썸네일

### 재료 전편 성과 지표

| 후보  | 영상            | 배수      | 조회수     | 좋아요 | 좋아요율  | 업로드 |
|-------|-----------------|-----------|------------|--------|-----------|--------|
| 1순위 | {짧은 제목}      | **{N}x**  | **{N}**    | {N}    | {N}%      | {날짜} |
| 2순위 | {짧은 제목}      | {N}x      | {N}        | {N}    | **{N}%**  | {날짜} |
| 3순위 | {짧은 제목}      | {N}x      | {N}        | {N}    | {N}%      | {날짜} |

| 후보  | 판정 |
|-------|------|
| 1순위 | {사유} → **확정** |
| 2순위 | {사유} → **A/B 대조군** |
| 3순위 | {사유} → **후보에서 제외** |

- 1순위 — [{전체 제목}]({url})
- 2순위 — [{전체 제목}]({url})
- 3순위 — [{전체 제목}]({url})

### 지표가 엇갈리는 지점

{지표마다 우열이 뒤집히는 곳을 반드시 짚는다}
{지표 간 우선순위와 그렇게 판단한 이유}

### A/B 테스트 권고

{넣을지 여부 + 넣는다면 어느 조합}
```

**A/B 테스트 판단 기준** — 유튜브 「테스트 및 비교」는 썸네일 **최대 3장**을 실트래픽으로 겨룬다.

| 상황 | 권고 |
|---|---|
| 1·2순위의 배수·좋아요율이 **엇갈린다** | ⭕ 테스트 권장 — 어느 쪽이 이길지 지표로 못 가른다 |
| 1순위가 모든 지표에서 앞선다 | 넣어도 좋지만 실익 적음. 2순위를 대조군으로 1장만 추가 |
| 하위 후보가 **1자릿수 배수** | ❌ 넣지 않는다. 검증 실패한 썸네일을 실트래픽에 태우는 것은 손해 |

> ⚠️ 테스트 기간에는 노출이 분산되므로, **업로드 직후 상승 구간을 테스트로 소모할지**는 사용자 판단이다. 권고만 하고 강요하지 않는다.

→ 사용자 확인 후 다음 단계

## STEP 5: 인트로 대본 작성

### 채널 프로필 반영
- `config/profile.md`의 톤, 말투, 금지 표현, 시그니처 표현을 따름
- 채널 성격에 맞는 자연스러운 인트로 작성

### 인트로 구조

1. **훅 (1~3문장)**
   - 통합본에 포함된 영상들의 핵심 키워드/충격 포인트를 활용
   - 시청자가 "이건 봐야겠다" 싶게 만드는 도입부
   - 숫자, 대비, 역설 등 활용

2. **영상 소개 (1~2문장)**
   - 어떤 영상들을 묶었는지 간결하게 설명
   - "이번 영상은 ~, ~, ~ 세 편을 하나로 엮은 통합편입니다" 형태

3. **시청 안내 (1~2문장)**
   - 긴 영상임을 자연스럽게 안내
   - 편하게 들을 수 있다는 메시지
   - **벤치마킹과 표현이 겹치지 않도록** 자연스럽게 변형

4. **기대 효과 + 시작 (1~2문장)**
   - 끝까지 보면 얻을 수 있는 것
   - "그럼 바로 시작하겠습니다" 등으로 마무리

### 필수 규칙
- 채널 profile.md의 금지 표현을 사용하지 않는다
- 시그니처 표현은 인트로에서는 아껴둔다 (본편에서 사용할 것이므로)
- 총 길이: 150~250자 내외
- 벤치마킹 채널 인트로와 동일한 문장 구조를 그대로 쓰지 않는다
- **직전 통합본들의 인트로를 먼저 읽고 문장 구조·표현이 겹치지 않게 한다.** 통합본은 같은 채널에 반복해서 나가므로 시청 안내 문구("편하게 틀어두고…")가 매번 같으면 양산형으로 읽힌다

### 🔴 TTS 규격 (본편 대본과 동일하게 적용한다)

**인트로도 TTS에 올라가는 대본이다. `prompts/tts-rules.md`를 본편 `script.txt`와 똑같이 지킨다.**
규칙 원본은 `tts-rules.md` 한 곳이므로 여기에 다시 옮겨 적지 않는다. 자주 놓치는 지점만 짚는다.

| 항목 | 인트로에서 특히 주의할 점 |
|---|---|
| 특수문자·이모지 | 기획 문서 감각으로 `—`, `·`, `※`를 쓰기 쉽다. 낭독 대상에는 쓰지 않는다 |
| 단어 뒤 괄호 | 「폭스콘(Foxconn)」처럼 쓰지 않는다 |
| URL·이메일 | 인트로에 넣지 않는다 |
| 숫자 표기 (8번) | **기계가 검사하지 못하는 유일한 항목이라 반드시 눈으로 대조한다.** 고유어 단위(개·명·살·가지·곳)는 고유어, 한자어·외래어 단위(톤·미터·년·원)는 한자어 또는 아라비아 |
| 한 줄 형식 | 정본은 한 줄이다. `intro.md`의 문단 나눔은 사람이 읽기 위한 것이고, 정본에는 남지 않는다 |

### 작성 후

1. 인트로 전문을 사용자에게 보여주고 피드백 수렴 → 수정 요청 시 해당 부분만 수정
2. 확정되면 `intro.md`에 저장한다. 아래쪽에 `---`로 구분해 **검수 체크**를 남긴다
   (금지 표현 / 독재자 존칭 / 시그니처 절약 / 직전 통합본과의 중복 회피 / 숫자 표기 대조표)
3. **`finalize_intro.py`로 TTS 정본을 뽑는다.** 손으로 한 줄로 이어 붙이지 않는다

```bash
# macOS/Linux
.venv/bin/python scripts/finalize_intro.py --dir "channels/{ch}/projects/{proj}/_compilation"
# Windows
.venv\Scripts\python scripts\finalize_intro.py --dir "channels\{ch}\projects\{proj}\_compilation"
```

- `intro.md`의 **첫 `---` 앞까지**만 낭독 대상으로 잘라내므로, 검수 체크는 반드시 `---` 아래에 쓴다
- 본편 `finalize.py`와 **같은 함수**를 호출한다 (규칙 집행자는 한 곳이다)
- 리포트에 보정 건수가 뜨면 그건 **인트로 원문이 규격을 어겼다는 뜻**이다. 자동 보정을 믿고 넘기지 말고 `intro.md` 원문을 고친 뒤 다시 돌린다
- 산출물은 `intro_script.txt` — **TTS에 올리는 파일은 이것이다**

## STEP 7: 인트로 자막 SRT 생성 (선택)

사용자가 인트로 대본으로 **TTS 오디오를 만들어 온 뒤** 진행하는 단계.
대본이 정답 텍스트이므로 오디오에서는 **타이밍만** 가져와, 오타 없는 자막을 정확한 타임코드로 생성한다.

### 트리거
- STEP 6 이후 사용자가 오디오를 넣고 "자막 만들어줘", "SRT 뽑아줘", "오디오 넣었어" 등
- `_compilation/` 폴더에 오디오 파일(mp3/wav)이 새로 들어와 있음

### 7-1. 오디오 확인
- `_compilation/` 폴더를 스캔해 오디오 파일(.mp3/.wav/.m4a)을 찾는다
- 여러 개면 어느 것이 인트로 오디오인지 사용자에게 확인
- 없으면: "인트로 TTS 오디오를 `_compilation/` 폴더에 넣고 알려주세요" 안내

### 7-2. 자막 덩어리(chunks) 작성
**`intro_script.txt`** 를 **호흡·의미 단위**로 쪼개 `_compilation/intro_chunks.txt`에 한 줄에 하나씩 저장한다.
(`intro.md`가 아니다 — TTS가 실제로 읽은 텍스트는 정본인 `intro_script.txt`이고, 정렬 정확도는 이 일치에서 나온다)

**끊기 기준:**
- 쉼표·절 단위로 짧게 끊는다. 문장 중간이라도 자연스러운 호흡 지점에서 자른다
  - 예: "그런데 그 속을 까보면 기름 없어서 못 움직이는 탱크," → 여기서 끊고 다음 자막으로
- 나열은 한 덩어리로 유지한다
  - 예: "북한군 128만, 핵무기 수십 발, 병력 수 세계 4위." → 통째로 한 줄
- 한 줄이 너무 길지 않게 (화면 한 줄에 들어갈 분량, 대략 30자 내외 권장)
- 자막 텍스트는 `intro.md` 원문과 **철자 그대로** 유지 (정렬 정확도 핵심). "—" 같은 표시용 기호만 제거

### 7-3. 강제 정렬 실행
`scripts/align_srt.py`를 실행한다. (OS별 python 경로 사용)

```bash
# macOS/Linux
.venv/bin/python scripts/align_srt.py \
    --audio "channels/{ch}/projects/{proj}/_compilation/{오디오파일}" \
    --chunks "channels/{ch}/projects/{proj}/_compilation/intro_chunks.txt" \
    --out "channels/{ch}/projects/{proj}/_compilation/intro.srt"

# Windows
.venv\Scripts\python scripts\align_srt.py --audio "..." --chunks "..." --out "..."
```

**엔진 (기본 `ctc`):**
- **ctc** (권장/기본): ONNX MMS wav2vec2 **CTC 강제정렬**. 정답 대본을 프레임 단위(20ms)로 정렬 → ASR·보간이 없어 **오차 최소**. torch 불필요.
  - 첫 실행 시 ONNX 정렬 모델이 `scripts/.models/`에 자동 다운로드된다 (약 1GB, 1회)
  - 단어 수가 대본과 정확히 일치해야 하며, 불일치 시 자동으로 whisper로 폴백한다
- **whisper** (`--engine whisper`): faster-whisper ASR 타임스탬프 정렬. 근사치라 CTC보다 부정확. CTC가 실패할 때만.

**옵션:**
- **텀(빈 구간) 제거는 기본 ON.** 각 자막을 다음 자막 시작 시점까지 유지해 빈 구간을 0으로 만든다. 자연 쉼을 살리려면 `--keep-gaps`.
- 자막이 전반적으로 늦게 뜨면 `--lead 0.12` (0.12초 앞당김) 식으로 조정.

- 스크립트가 콘솔에 타임코드 미리보기를 출력한다

### 7-4. 결과 보고 + 미세 조정
- SRT 타임코드를 표로 보여주고 [intro.srt](...) 클릭 링크로 보고
- "오디오 재생하며 확인하시고, 특정 줄이 빠르거나 늦으면 번호를 알려주세요" 안내
- 전체가 밀리면 → `--lead` 값을 줘 재실행
- 특정 줄 하나만 어긋나면 → `intro.srt`를 Edit tool로 해당 타임코드만 직접 수정 (재정렬 불필요)
- **100% 자동 무오차는 불가**하다. CTC로 오차를 최소화하되, 마지막 미세 오차는 위 두 방법으로 보정하는 것이 원칙.

### 에러 처리
- ctc-forced-aligner 미설치 → `.venv/bin/pip install ctc-forced-aligner unidecode` (Windows: `.venv\Scripts\pip`)
- `unidecode` 없음 오류 → 위와 동일하게 `unidecode` 설치 (CTC의 한국어 로마자화 의존성)
- CTC가 whisper로 폴백하면 → faster-whisper 미설치 시 `.venv/bin/pip install faster-whisper`
- 인식/정렬 실패 → 오디오와 대본 내용이 일치하는지 확인 (다른 대본으로 TTS를 만든 건 아닌지)

## 필수 규칙

0. **재료 기록은 빠뜨리지 않는다**
   - 시작 전 `compilation-ledger.md` 대조(STEP 0), 완료 시 원장 갱신(STEP 6). 둘 다 필수다
   - 재료를 **길이 산술로 추측하지 않는다.** plan.md 기록 + 유튜브 설명란 두 곳으로 확인한다

1. **script-pd와 절대 간섭 금지**
   - `_refs/`, `_script/` 폴더를 생성하거나 접근하지 않는다
   - `_compilation/` 폴더만 사용한다
   - script-pd의 상태 감지에 영향을 주는 파일을 만들지 않는다

   - 한글 텍스트를 bash heredoc(cat <<EOF)으로 파일에 쓰지 않는다

3. **크로스 플랫폼**
   - yt-dlp 경로: macOS `.venv/bin/yt-dlp`, Windows `.venv\Scripts\yt-dlp`
   - 디렉토리 생성: `python -c "import os; os.makedirs(...)"`

4. **산출물 링크**
   - 완료 보고 시 workspace 상대경로로 작성하여 클릭 가능하게 한다

5. **에러 처리**
   - yt-dlp 오류 → "yt-dlp 업데이트 필요" 안내
   - venv 오류 → ".venv 확인" 안내

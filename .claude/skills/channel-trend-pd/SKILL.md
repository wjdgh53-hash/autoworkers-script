# Channel Trend PD

채널 진단 → 히트작 DNA(제목 공식·썸네일 프레임·구조) 계승 → 최신 트렌드 결합 → 주제 확정까지 하고, 기존 `script-pd`로 인계하는 스킬.

## ⛔ 시작 전 자가 점검 (Phase 0보다 먼저)

이 스킬을 실행하기 전에 **아래 조건 중 하나라도 만족하는지 확인**한다. 하나도 해당 없으면 **즉시 중단하고 `script-pd`로 넘긴다.**

- [ ] 메시지에 **채널 URL**이 있다 (`/@핸들`, `/channel/UC...`, `/c/...`, `/user/...`, 끝이 `/videos`)
- [ ] 메시지에 **명시적 진단·기획 의도**가 있다 ("채널 진단", "채널 분석", "다음 컨텐츠 기획", "결 맞춰서 다음 거", "성적 어때")
- [ ] **레퍼런스도 없고 주제도 없다** — 사용자가 "무엇을 만들지"부터 정해 달라고 한다 ("오늘 소재 추천해줘", "오늘 뭐 올리지", "주제 알아서 정해줘")
- [ ] URL이 전혀 없는데 사용자가 채널 단위 기획을 요청했다

> **가장 직관적인 판별 기준: 「무엇을 만들지가 정해져 있는가」**
> - 주제나 레퍼런스가 **있다** → `script-pd` (만들기만 하면 된다)
> - 주제도 레퍼런스도 **없다** → **이 스킬** (무엇을 만들지부터 정해야 한다)

**영상 URL(`watch?v=`, `youtu.be/`, `/shorts/`) 하나 또는 여럿 + "대본 만들어줘"** → 이 스킬 대상 **아님**. 그 URL들은 레퍼런스이므로 `script-pd`의 COLLECT로 바로 넘긴다.

애매하면 스캔·수집을 돌리기 전에 **사용자에게 먼저 물어본다.** (잘못 판단하고 진행하면 yt-dlp 스캔·수집이 헛돈다)

## 핵심 원칙 (설계 철학)

1. **소재보다 프레임·구조가 먼저다.** 롱폼은 클릭을 따야 내용물을 보여줄 수 있다. 소재 중심으로 남의 채널 레퍼를 찾으면 내 채널 결을 잃는다. → **채널 자기 자신의 히트작**을 앵커 레퍼로 삼아 프레임·구조를 계승하고, 소재만 신선한 트렌드로 갈아끼운다. 그래서 남과 안 겹치고 독창적이면서 결이 유지된다.
2. **DNA는 매번 새로 뽑는다(동적).** 발동할 때마다 "현재 최고작"에서 제목 공식·썸네일 프레임·구조를 새로 추출한다. 채널 결은 진화하므로 고정 공식에 의존하지 않는다. (`config/pd-guide.md`의 제목 공식 섹션은 참고 기본값일 뿐)
3. **트렌드 검색은 DNA 조건부다.** "요즘 뜨는 이슈"를 그냥 찾으면 남과 겹친다. 히트작 DNA의 **구조 조건에 끼워지는** 최신 이슈만 고른다.
4. **config는 고정, URL은 진단 대상만 결정.** 사용자는 경제 채널 3개를 `channels/detective-economy/` config 하나로 운영한다(결 동일). 준 채널 URL은 "어느 채널을 스캔·진단할지"만 정하고, 말투·장르·시그니처는 항상 detective-economy config를 쓴다. 완성 대본은 3채널 어디든 업로드 가능(youtube.md에 채널명 금지).
5. 🔗 **근거 영상은 링크를 반드시 병기한다.** 제목·조회수·배율만 쓰고 URL을 빠뜨리지 않는다. 숫자만으로는 사용자가 그 영상을 열어 썸네일·제목·구성을 확인할 수 없어 추천을 검증할 수 없다. **아래 규칙 5-1이 이 스킬의 모든 표에 적용된다.**

### 5-1. 링크 병기 규칙 (모든 산출 표 공통)

- 영상이 등장하는 **모든 표에 `[영상](https://www.youtube.com/watch?v={id})` 열을 넣거나 제목 자체를 링크로 만든다.**
- 적용 대상: Phase 2 최근 성적표·축별 판정표, Phase 4-2 결 판정표, Phase 4-5 후보 제시, Phase 4.5 레퍼 세트표(주·보조·**반증**·앵커), Phase 6 진단 스냅샷, `config/_benchmarks/channels.md`, `production-queue.md`
- 채널을 언급할 때도 채널 URL을 병기한다
- 유튜브 URL은 전체 주소로 쓴다(워크스페이스 상대경로 규칙은 저장소 **파일**에만 적용된다)

> **근거(2026-08-16 정호님 지적)**: 배율 표만 보고는 그 영상을 직접 볼 수 없어 추천을 수락·기각할 판단 재료가 없다.

## 발동 트리거

**발동한다:**
- 메시지에 **유튜브 채널 URL**(`/@핸들`, `/channel/UC...`, `/c/...`, `/user/...`, `/videos`)이 있는 경우 — 뒤에 붙는 말이 "대본 만들어줘"든 "진단해줘"든 무관
- URL 없이 "다음 컨텐츠 기획해보자 / 채널 진단해줘 / 결 맞춰서 다음 거 만들자" → 어느 채널인지 물어보고, 지정 없으면 기본 채널(detective-economy) 최근 업로드 스캔
- **소재 추천 요청 — 레퍼런스도 주제도 없을 때**: "오늘 소재 추천해줘", "오늘 뭐 올리지", "오늘 뭐 만들까", "주제 알아서 정해줘", "레퍼 없는데 대본 만들어줘", "뭐가 좋을까"
- **영상 URL** + 명시적 진단·기획 문구("이 채널 진단해줘", "이 채널 다음 컨텐츠 기획해보자") → 영상에서 소속 채널을 역추적해 진행

**발동하지 않는다 (→ `script-pd`):**
- ⚠️ **영상 URL**(`watch?v=`, `youtu.be/`, `/shorts/`) + "대본 만들어줘" — 그 영상은 **레퍼런스**다. 채널 스캔 대상이 아니다.
- 영상 URL 여러 개 / 재생목록 URL + "대본 만들어줘" — 전부 레퍼런스
- **주제가 이미 정해져 있는 경우** — "{주제}로 대본 만들어줘". 레퍼가 없어도 주제가 있으면 script-pd가 레퍼를 찾는다
- "이어서 해줘 / 다시 써줘 / 산출물 다시 줘" — 로컬 프로젝트 재개

> **분기 신호는 "URL 유무"가 아니라 「무엇을 만들지가 정해져 있는가」다.**
> 주제·레퍼가 있으면 → `script-pd`. **둘 다 없어서 정하는 것부터 해야 하면 → 이 스킬.**
> 의도 문구가 명시적이면 그것이 URL 종류보다 우선한다.

> ⚠️ **"오늘 소재 추천해줘"에서 절대 하면 안 되는 것: 바로 소재를 떠올려 제시하는 것.**
> 이 스킬은 반드시 **Phase 1 스캔부터** 시작한다. 채널 최근 성적을 안 보고 낸 추천은 근거가 없고, 실제로 실패한 전례가 있다(2026-08-15 사용자 지적). 스캔 → 축별 판정 → DNA → 수요 검증을 거친 뒤에만 후보를 낸다.

## Phase 0-A — ⚡ 빠른 경로: 대기열 소진 (Phase 1보다 먼저 판별)

### 트리거 — 「다음」이 들어가면 대기열이다

```
⚡ 대기열 (이 경로)     "다음 거 만들어줘"      "다음 대본 만들어줘"
                       "다음 편 만들어줘"      "다음 소재로 가자"
                       "그다음 거 만들어줘"    "순서대로 다음 거"
                       "다음 순번 제작"        "대기열 다음 거"
                       "큐에서 다음 소재로"    "저번에 정한 다음 거"

🔄 진행 중 프로젝트     "이어서 해줘"  "계속해줘"  "마저 해줘"
   (→ script-pd)       → 이건 대기열이 아니라 **하던 작업 재개**다
```

> **판별 기준 한 줄: 「다음」이면 새 소재(대기열), 「이어서·계속」이면 하던 것.**
> 애매하면 진행하지 말고 묻는다 — 잘못 타면 엉뚱한 프로젝트를 건드리거나 헛스캔이 돈다.

> 🚨 **이 경로는 Phase 1~4를 통째로 건너뛴다.** 대기열에 있는 소재는 **이미 그 과정을 거쳐 검증된 것**이라 다시 돌리는 게 낭비다.
> 전체 스캔은 반나절짜리 작업이고, 축은 매주 바뀌지 않는다.

### 🚨 0단계 — 어느 채널인지부터 확정한다 (채널이 여러 개다)

**대기열은 채널마다 따로 있다.** 채널을 안 정하고 항목을 꺼내면 다른 채널 소재로 대본을 쓰게 된다.

1. 사용자 메시지에 채널이 명시됐는지 본다
   | 말 | 채널 |
   |---|---|
   | 탐정 / 탐정경제학 | `detective-economy` |
   | 방구석 / 방구석경제 / 방구석economy | `bangguseok-economy` |
2. **명시가 없으면 대기열이 있는 채널을 전부 찾는다** — 채널을 하드코딩하지 않는다
   ```bash
   # macOS/Linux
   ls channels/*/production-queue.md
   # Windows
   dir /b /s channels\*\production-queue.md
   ```
3. 대기열이 **1개뿐이면** 그 채널로 진행하고, 어느 채널인지 한 줄 알린다
4. 🔴 **2개 이상이면 사용자에게 묻고 답을 기다린다.** 기본값·최근 사용 채널로 밀지 않는다
   - 각 대기열의 **미제작 1순위 제목과 배율을 나란히 보여주며** 묻는다. 그래야 보고 고를 수 있다
   - 형식 예시:
     ```
     어느 채널로 갈까요?

     | 채널 | 다음 순번 | 배율 |
     |---|---|---|
     | 탐정경제학 | 2. 현대판 식민지 전략 | 2.6배 |
     | 방구석 경제 | 2. {제목} | {N}배 |
     ```
   - `AskUserQuestion` 도구를 쓰지 않는다. **채팅 본문 마크다운으로 묻는다**

### 절차 (채널 확정 후 5분 이내로 끝낸다)

1. `channels/{확정 채널}/production-queue.md`를 Read한다
2. **상태가 `미제작`인 가장 위 항목**을 꺼낸다. `제작 완료`·`진행 중`·`부분 제작`은 건너뛴다
   - ⚠️ 채널마다 **추가 제약이 있을 수 있다.** 예: 방구석 경제는 "1~6번은 전부 축 A, 중간에 다른 축을 끼우지 않는다"가 파일에 명시돼 있다. **대기열 상단의 공통 체크리스트·금지선을 먼저 읽고 따른다**
3. **원본 레퍼의 현재 배율만 재확인한다** — `yt-dlp`로 그 영상 1편 + 채널 중앙값용 최근 10편
   - 배율이 **3배 미만으로 떨어졌으면** 그 항목을 보류하고 다음 순번으로 내려간다(사유를 파일에 적는다)
   - 채널이 **1개월 이상 업로드가 끊겼으면** 제재 의심으로 제외한다
4. **소재가 3개월 이상 묵었으면** 최신 수치 갱신이 필요하다고 인계 시 명시한다
5. 앵커 레퍼는 **우리 채널 최신 히트작으로 갱신**한다 — 대기열 항목에는 원본 레퍼만 적혀 있고 앵커는 시간이 지나면 바뀐다. 최근 15편만 스캔해 조회수/일 1위를 고른다
6. 레퍼 세트(주·보조·**반증**·앵커)를 Phase 4.5 규칙대로 확정하고 `script-pd`로 인계한다
7. 대기열 파일에서 그 항목 상태를 **`제작 착수`로 바꾼다.** 완료 후에는 `제작 완료`로 다시 바꾼다

### ⛔ 이 경로를 쓰면 안 되는 때 → 전체 스캔(Phase 1)으로 간다

- **대기열에 `미제작` 항목이 없다**
- **최근 3편 성적이 창 중앙값 아래로 떨어졌다** — 축이 흔들렸다는 신호다. 대기열 전체를 다시 판정해야 한다
- 사용자가 "소재 추천해줘 / 오늘 뭐 올리지"처럼 **무엇을 만들지부터 정해 달라고** 했다
- 대기열 마지막 갱신이 **한 달 이상 지났다**

## Phase 0 — 채널 매핑

- 준 URL이 어느 유튜브 채널인지 확인. config는 **항상 `detective-economy`** 고정.

## Phase 1 — SCAN (yt-dlp)

최근 업로드의 조회수·업로드일·길이를 수집한다. **flat 모드는 조회수(NA)가 안 나오므로 2단계로 한다.**

1. 영상 ID·제목 목록(최근 25개):
```bash
{YTDLP} --flat-playlist --playlist-end 25 --print "%(id)s ||| %(title)s" "{채널URL}/videos"
```
2. 각 영상의 실측 메타(조회수·업로드일·길이):
```bash
{YTDLP} --no-warnings --print "%(upload_date)s | %(view_count)s | %(duration)s | %(id)s | %(title).50s" "https://www.youtube.com/watch?v={id}"
```
   - 여러 ID를 순회(반복문). 실패(수집 오류)하면 임의 진행 금지 → 사용자에게 알리고 확인([[feedback_ref_collect_fail_ask]] 취지).

### 형제 채널 교차 스캔 (같은 대본을 여러 채널에 올리는 경우 필수)

사용자는 경제 채널 여러 개를 **같은 config·같은 대본**으로 운영한다([[project_three_economy_channels]]). 이때 진단 대상 채널만 보면 **채널 문제와 대본 문제를 구분할 수 없다.**

- 형제 채널이 있으면 **같은 방식으로 최근 10~15편을 함께 스캔**한다.
- **같은 날/같은 대본이 올라간 편을 짝지어 조회수를 비교**한다. 이게 통제 실험이 된다.
- 판정:
  - 한 채널에서만 저조 → **채널 문제**(알고리즘 학습 방향·제재 정황). 대본을 고칠 일이 아니다
  - 양쪽 다 저조 → **대본·소재 문제**
- **축별로 갈리는지 확인한다.** 채널이 통째로 죽은 게 아니라 특정 소재축만 죽는 경우가 실제로 나온다.

> **실측(2026-08-15)**: 같은 대본이 럭키경제학 142회 / 탐정경제학 4,103회로 **29배** 갈렸다. 럭키가 죽은 게 아니라 축이 갈린 것이었다 — 럭키는 국내 생활밀착(유흥업계 27,372·시골땅 178,783)이 살아 있고 중국·국제만 죽었으며, 탐정은 정반대였다.
> → 이 발견이 "동일 대본 양채널 업로드 중단 + 재고 대본 채널별 배분"이라는 결론으로 이어졌다. **형제 채널을 안 봤으면 못 나왔을 결론이다.**

## Phase 2 — 진단 (앵커 히트작 선정)

수집 데이터로 **계승할 앵커 히트작**을 고른다.

### 선정 규칙
1. **오늘 날짜** 확인(`date`), 각 영상의 나이(age_days) 계산.
2. **갓 올린 1~2개(72h/3일 미만) 제외** — 판단 불가(조회수 미성숙).
3. **최근 창 설정 — 휴지기 자동 감지**: 최근 업로드들의 연속 간격 중 **가장 큰 공백**을 찾는다. 30일 이상 공백이 있으면 "재개 후" = 그 공백 이후 업로드만 창으로. 공백 없으면 최근 15개 또는 최근 60일.
4. 창 안에서 각 영상 **조회수/일 = views ÷ max(age_days,1)** 계산. **조회수/일 최고**가 앵커.
5. **이상치 판정**: 앵커의 조회수/일이 창 중앙값의 **2배 이상**이면 "강한 계승 신호". 미만이면 앵커로 쓰되 **"확신 낮음"** 명시(억지 계승 금지).

### 소재 축별 판정 (필수)

앵커 1편만 고르고 끝내지 않는다. **창 안의 영상을 소재 축으로 묶어 축별 평균 조회수/일을 낸다.**

- 축 예시: 방향 역전형 / 세계가 등 돌림형 / 소수민족 저항형 / 내부 문제 나열형 / 북한·러시아형 / 재테크·재난사형
- 축별 평균이 **창 중앙값의 5분의 1 이하**로 떨어지면 **중단 권고**를 리포트에 명시한다. 그 축은 다음 소재 후보에서 제외한다
- 반대로 중앙값의 **3배 이상**인 축이 있으면 Phase 4의 트렌드 조건을 그 축으로 좁힌다

> **왜 필요한가**: 앵커 1편만 보면 "이 프레임이 통한다"까지만 나온다. 축별로 묶어야 **"이 축은 즉시 접어야 한다"**가 나온다.
> **실측(2026-08-15)**: 북한·러시아 축 5편 평균 28회/일 vs 방향 역전형 2편 평균 2,730회/일 — 같은 채널 안에서 **97배**. 앵커만 봤으면 "북·러를 접어라"는 결론이 안 나왔다.

### 진단 리포트 (사용자에게 제시)
- 최근 성적표(표: 날짜·제목·조회수·길이)
- **소재 축별 판정표**(축·편수·평균 조회수/일·판정)
- 앵커 히트작과 왜 이게 최고인지
- 형제 채널을 스캔했으면 **짝 비교표**와 채널/대본 판정
- 저조/부진 패턴이 보이면 솔직히 진단한다. 듣기 좋게 다듬지 않는다

## Phase 3 — DNA 추출 (앵커에서 매번 새로)

앵커 히트작을 수집·분석해 **계승할 DNA 브리프**를 만든다.

1. 앵커를 레퍼로 수집:
```bash
{VENV_PYTHON} scripts/collect.py --project {신규프로젝트} --channel "detective-economy" "{앵커URL}"
```
   - 신규 프로젝트명: 선택 주제 확정 후 명명하므로, 이 단계는 임시로 진단용 폴더에 받거나 주제 확정 후 수집해도 된다(순서는 유연). 권장: **주제 선택(Phase 5) 후** collect → script-pd 인계 시 함께 처리.
2. **DNA 브리프** 항목(앵커의 meta·thumbnail·transcript에서 추출):
   - **제목 공식**: 앵커 제목의 골격(예: `"[결핍 훅]" [강대국 주어] [숫자] [역전 행동] 이유`). 구성 요소 분해.
   - **썸네일 프레임**: 구도 패턴(A vs B/스케일 대비 등)·핵심 오브젝트·색채·텍스트 레이아웃.
   - **구조·리텐션**: 훅 방식, 오픈루프, 시그니처 운용, 감정 아크, 다층 반전 여부.
   - **감정 엔진**: 무엇이 시청자를 움직였나(예: 자부심+뺏길 위기감).
   - **길이 신호**: 앵커 길이 + 창의 길이-성적 상관.
   - **트렌드 조건**: 이 프레임에 끼워지려면 소재가 갖춰야 할 구조 조건(예: 강대국 foil + 한국 급소/강대국 몰락 + 구체 숫자, 경제·산업 소재, 순수 과학·기업경영·전쟁사 회피).
   - **금지**: 앵커 고유 표현·비유(복제 금지, 소재만 계승).

> 무거운 정밀 분석(analysis.md·patterns.md)은 Phase 6에서 script-pd가 앵커를 레퍼로 다시 수행하므로, 여기선 진단·트렌드 조건에 쓸 **가벼운 브리프**면 충분하다.

## Phase 4 — 트렌드 결합 + 소재 수요 검증

DNA 브리프의 **트렌드 조건**에 맞는 최신 이슈를 찾아 주제 후보를 만든다.

### 4-1. 뉴스 축 — DNA 조건부 WebSearch

1. 최근 1~2개월 이슈 중 프레임에 끼워지는 것만. 채널 장르(경제/시사) × 구조 조건(강대국 foil·한국 급소·구체 숫자 등)으로 좁힌다.
2. **중복 제거**:
   - 기존 프로젝트와 겹침 확인: `channels/detective-economy/projects/` 폴더명 스캔.
   - 타 유튜버 포화도: 이미 많이 다뤄진 소재면 앵글 차별화 또는 제외.

### 4-2. 🚨🚨 결(소재축) 일치가 배율보다 먼저다 — 이 절을 건너뛰면 대본이 죽는다

> 🔴 **2026-08-16 실측 — 이 규칙이 없어서 대본 하나가 통째로 실패했다.**
> `china-wealth-exodus-korea`는 CTR 5.2%로 클릭은 됐는데 **13시간 노출 970 / 조회 68 / 평균 시청 지속 4:10(평소 -2:12)** 으로 죽었다.
> 원인은 패키징이 아니라 **소재축 이탈**이었다. 4-3의 배율 검증은 전부 통과했는데도 실패했다.

**우리 채널이 반응하는 소재축을 먼저 확정하고, 그 축 안에서만 후보를 만든다.**

#### ㉠ 벤치마크 채널을 "체급"이 아니라 "축"으로 고른다

| ❌ 하면 안 되는 것 | ⭕ 해야 하는 것 |
|---|---|
| `ytsearch`로 소재 키워드를 던져 **아무 채널이나** 배율 높은 편을 주 레퍼로 삼는다 | **우리 채널과 소재축이 같은 채널**을 먼저 정하고, 그 채널 안에서 배율을 잰다 |
| 구독자 체급이 비슷하면 결도 비슷할 것이라 가정한다 | 체급이 비슷해도 **히트 소재축이 다르면 결이 다른 채널**이다. 최근 10편의 소재를 직접 읽고 판정한다 |

- 🚨 **가장 먼저 `channels/detective-economy/config/_benchmarks/channels.md`를 Read한다.** 결이 같다고 이미 판정된 채널 목록과, 결이 달라 **쓰면 안 되는 채널 목록**이 거기 있다. 밖에서 `ytsearch`로 새로 찾는 것은 그다음이다
- 축 판정 방법: 후보 채널 최근 15~20편의 **제목만 읽고 소재축을 분류**한다. 우리 채널 Phase 2의 축별 판정표와 **겹치는 축이 과반**이어야 결이 같은 채널이다
- 새로 판정한 채널은 결과(결 같음/다름 + 근거 배율표)를 `_benchmarks/channels.md`에 **추가해 둔다.** 다음 회차에 같은 판정을 다시 하지 않기 위해서다

> **실측(2026-08-16)**: 「부자의 경제학」(3.68만)은 체급이 비슷해 주 레퍼로 삼았으나, 그 채널의 히트축은 **한국 국내 이슈(부동산·정치·기업)** 였다. 우리 채널 축(중국·국제정세)과 달랐다.
> 정작 결이 같은 채널은 **@ShinyGold0**(구독 7,960, 중국 국제정세 전문)이었고, **이미 우리 앵커 레퍼 001의 출처 채널이었다.** 밖에서 찾을 필요가 없었다.

#### ㉡ 🔴 무대(舞臺)를 옮기지 않는다 — 착지와 무대는 다르다

**"한국 착지"는 마지막에 우리 얘기로 꺾는 것이지, 한국을 본문의 무대로 삼는 것이 아니다.**

- 자사 앵커에서 **한국이 차지한 분량 비율을 재고**, 새 대본이 그 비율을 크게 넘기면 **후보 단계에서 기각**한다
- 무대는 앵커와 같아야 한다. 앵커의 무대가 중국·국제면 새 대본의 무대도 중국·국제다

> **실측(2026-08-16)**: 자사 앵커(8/14, 43배)에서 한국은 **마지막 6%**뿐인 관중석이었다. 그런데 실패작은 **한국 부동산·전세·규제가 본문의 절반**이었다.
> 시청자는 중국 몰락을 보러 들어왔다가 4분쯤에 한국 부동산 얘기를 만나고 나갔다 — 평균 시청 지속 4:10이 그 지점이다.

#### ㉢ 축이 같은 채널 안에서 "같은 소재의 실패작"을 먼저 찾는다

결이 같은 채널이 **우리가 하려는 소재를 이미 다뤘다가 죽었으면, 그 소재는 후보에서 즉시 뺀다.** 이것이 가장 싸고 확실한 검증이다.

> **실측(2026-08-16)**: @ShinyGold0에 `중국인이 한국 인천·제주 토지를 쓸어가는 이상현상`(08-08)이 **1,865회 = 채널 중앙값의 0.34배, 그 채널 최하위**로 이미 있었다.
> 같은 채널 `중국 청년들이 완전히 포기한`은 **202,745회(36.5배)**. **109배 차이.**
> 이 한 편만 봤으면 「중국 자본의 한국 부동산 유입」은 후보에서 바로 빠졌다.

### 4-2-1. 소재 수요 검증 — 축 판정을 통과한 뒤에만 돌린다

> ⛔ **뉴스 검색만으로 소재를 추천하면 안 된다.** "최근에 터진 이슈 + DNA 적합"은 **그 소재가 유튜브에서 팔린다는 증거가 아니다.**
> **사용자는 과거 이 방식으로 추천받은 소재가 처참히 실패한 경험이 있다.**(2026-08-15 사용자 직접 지적) 반드시 실적으로 검증한다.
>
> ⛔ **다만 배율 검증은 4-2의 축 판정을 통과한 채널·소재에만 적용한다.** 축이 다른 채널에서 배율이 아무리 높아도 그건 **우리 소재가 아니다.**(2026-08-16 실패)

후보마다 **유튜브에서 그 소재의 실제 성적을 뽑는다:**

```bash
{YTDLP} --no-warnings --extractor-args "youtube:lang=ko" --print "%(view_count)8s | %(upload_date)s | %(duration)5s | %(uploader).12s | %(title).45s" "ytsearch12:{소재 키워드}"
```

- 검색어를 **2~3개 각도**로 바꿔 돌린다(예: "중국 부자 해외 자산 유출" / "중국 부유층 탈출 이민").
- 롱폼(10분 이상)만 본다. 쇼츠·뉴스클립은 제외.

### 4-3. ⛔ 조회수 절대값으로 판단하지 않는다 — 배율로 판단한다

절대 조회수는 **채널 체급에 좌우되므로 아무 정보가 없다.** 두 배율을 모두 확인한다:

| 배율 | 계산 | 의미 |
|---|---|---|
| **구독자 대비** | 조회수 ÷ 구독자 수 | 체급 대비 도달. 1.0배 미만이면 평작 이하 |
| **채널 중앙값 대비** | 조회수 ÷ 그 채널 최근 10~14편의 **중앙값** | **이게 더 중요하다.** 그 채널에서 이 편이 이상치인지 |

채널 중앙값을 내려면 **후보 레퍼가 속한 채널의 최근 10~14편을 별도로 스캔**해야 한다. 이 스캔을 건너뛰면 배율을 알 수 없으므로 **검증한 것이 아니다.**

- **체급이 비슷한 채널(구독자 0.5~3배)의 레퍼를 우선한다.** 체급이 10배 이상 차이 나면 계승 근거로 약하다
- 채널 중앙값 대비 **3배 이상**이면 유효한 소재 레퍼

> **실측(2026-08-15)**: clark TV 270,760회는 커 보였지만 구독 120만이라 **0.23배 = 평작**이었다. 반면 부자의 경제학 82,785회는 구독 3.68만·채널 중앙값 8,575회라 **9.7배 = 진짜 이상치**였다. 절대값만 봤으면 정반대를 골랐다.

### 4-4. 레퍼 채널 건전성 확인 (제재 정황 배제)

배율이 좋아도 **채널 자체가 죽어 있으면 계승 대상이 아니다.** 후보 레퍼 채널의 최근 업로드 이력을 확인한다([[feedback_ref_not_by_views]]).

- **업로드가 1개월 이상 끊겼다** → 제재·중단 정황. 제외한다
- **어느 시점부터 조회수가 한 자릿수 배율로 급락** → 제재 의심. 제외한다
- **동일 제목·동일 길이의 복붙본이 검색에 같이 나온다** → 그 복붙본은 양산형 판정 사례로만 쓰고 계승하지 않는다

> **실측(2026-08-15)**: 콧수염경제학은 3.1배로 나쁘지 않았으나 **4월 9일 이후 4개월째 업로드 중단**이라 제외했다. 같은 검색에서 콧수염 41,068회 vs 제목·길이가 완전히 같은 복붙본 **0회** — 계승은 되고 복제는 안 된다는 증거를 같은 소재 안에서 얻었다.

### 4-5. 후보 제시

**후보 3~5개** 각각:
- [DNA 적합도 체크(요소별)] + [실제 근거 숫자·출처(WebSearch로 검증)] + [**소재 수요 검증 결과(배율)**] + [제목안(동적 공식 계승)] + [기존/타채널 중복 여부] + [강점/리스크]

후보 제시 시 **추천 1개**를 명시한다.

> ⛔ **수요 검증에서 배율이 안 나온 후보는 추천 1순위로 올리지 않는다.** 뉴스가 아무리 신선해도 마찬가지다.

## Phase 4.5 — 레퍼 세트 확정 (주 · 보조 · 반증 · 앵커)

주제가 정해지면 **성공 레퍼만 모으지 않는다.** 실패 레퍼를 반드시 함께 넣는다.

### 🚨 반증 레퍼를 넣는 이유

성공작만 N편 모으면 공통점이 너무 많아 **무엇이 성패를 갈랐는지 특정되지 않는다.** 같은 채널에서 같은 소재축을 다뤘는데 **실패한 편**을 같이 넣으면, 남는 변수 하나가 드러난다.

**가장 좋은 반증 레퍼의 조건** — 주 레퍼와 아래가 같을수록 좋다:
- 같은 채널 (구독자·시청자층 동일)
- 비슷한 시기 (알고리즘 환경 동일)
- 비슷한 길이대
- 같거나 인접한 소재축

> 🔴 **반증 레퍼는 「결이 같은 채널」에서 먼저 찾는다 (2026-08-16).**
> 결이 다른 채널의 실패작은 **우리에게 아무것도 알려주지 않는다.** 그 채널의 시청자가 다르기 때문이다.
> **실측**: 반증 레퍼를 「부자의 경제학」(한국 국내 이슈 축)에서 뽑아 "한국 착지가 없어서 실패했다"는 결론을 얻었는데, 그 결론이 오히려 대본을 한국 부동산으로 끌고 가 실패를 불렀다.
> 결이 같은 @ShinyGold0에는 **같은 소재의 실패작(0.34배)** 이 이미 있었고, 그건 정반대("한국이 무대라서 실패했다")를 말하고 있었다.
> → **반증 레퍼를 결 다른 채널에서 뽑으면 결론이 뒤집힌다.** Phase 4-2의 축 판정을 통과한 채널에서만 고른다.

이 조건이 맞으면 **사실상 통제 실험**이 되고, 남는 변수를 단일 요인으로 특정할 수 있다.

### 표준 레퍼 세트 (4편)

| 역할 | 무엇 | 배율 기준 |
|---|---|---|
| **주 레퍼** | 소재 수요 검증 1위 | 채널 중앙값 대비 최고 |
| **보조 레퍼** | 같은 채널·같은 방향의 중간 성적작 | 2~4배 |
| **반증 레퍼** | 같은 채널·같은 소재축의 **실패작** | **1배 미만** |
| **앵커 레퍼** | **우리 채널** Phase 2에서 고른 히트작 | 프레임·구조 계승용 |

### 반증 레퍼 취급 규칙 (필수)

- collect 시 함께 받되, **역할을 명시적으로 전달**한다. 그냥 넣으면 계승 대상으로 오해된다
- ANALYZE에서 반증 레퍼 담당 에이전트에게는 **`## 🚨 회피 목록` 섹션을 별도로 만들라**고 지시한다 — "우리 대본에서 반드시 피해야 할 것 N개"
- ⛔ **반증 레퍼를 앵커 후보·중앙값 계산에 넣지 않는다.** `prompts/creative-strategy.md`의 앵커 선정(조회수/일 1위)이 오염된다. Phase 6 인계 시 이 사실을 명시한다

> **실측(2026-08-15)**: 부자의 경제학 06-05(9.7배)와 08-06(0.56배)은 같은 채널·같은 소재축·비슷한 길이인데 **17배** 차이였다. 남는 변수가 **"한국 착지" 하나**로 특정됐고, 회피 목록 5개가 나왔다. 성공작만 3편 모았으면 절대 안 나왔을 결론이다.

## Phase 6 — script-pd 인계

1. **진단 스냅샷 저장**(채널 진화 추적용):
   - 경로: `channels/detective-economy/_diagnosis/{YYYY-MM-DD}_{채널핸들}.md`
   - 내용: 스캔일, 대상 채널, 최근 성적표, **소재 축별 판정표**, **형제 채널 짝 비교**, 앵커 히트작, DNA 브리프, **검토했다 버린 후보와 기각 사유**, 선택 주제, **확정 레퍼 세트(역할·배율·영상 ID)**. (Python `open(...,encoding='utf-8')` 또는 Write tool로 저장)
2. **script-pd 발동** — 인계 시 명시 전달:
   - 채널: detective-economy
   - 신규 프로젝트명 + 확정 주제
   - **레퍼 세트 전체와 각 편의 역할**(주/보조/**반증**/앵커) + 배율. Phase 4.5에서 확정한 그대로.
     - ⛔ **반증 레퍼는 실패작이라는 사실을 반드시 전달**한다. 안 하면 script-pd가 계승 대상으로 오해한다
     - ⛔ **반증 레퍼를 앵커 후보·조회수/일 중앙값 계산에서 제외**하라고 명시한다. `prompts/creative-strategy.md`의 앵커 선정 로직이 오염된다
   - **DNA 브리프**(동적 추출본) → STRATEGY(제목·썸네일)·DRAFT에서 계승 지침으로 사용. pd-guide 고정 공식과 충돌 시 **DNA 브리프 우선**.
   - 목표 러닝타임 — **사용자에게 묻는다.** 길이로 성패를 예단하지 않는다. 앵커 히트작 길이는 참고로만 전달하고, 특정 분량을 규칙으로 강제하지 않는다
3. 이후 collect → analyze → data_prep → strategy → outline → draft → review → script.txt 전 과정은 script-pd가 그대로 수행.

# Script Reviewer

## 역할

작성된 대본 초안(draft.md)을 검수 체크리스트 기준으로 엄격히 검토하고, **신규 주장이 있으면 즉시 WebSearch로 검증**한 뒤 **verdict(통과/수정)를 직접 판단**한다.

## 입력

SKILL.md(PD)가 Task tool로 호출 시 전달:
- draft.md 내용
- outline.md 내용
- concept.md 내용
- verified-data.md 내용
- 검수 체크리스트 (prompts/script-review-checklist.md)
- **문체 가이드 (prompts/tone-guide.md)** — 문체 검수의 판정 기준. 대조쌍이 규칙 문장보다 우선한다
- **`check_tone.py` 실행 결과 전문** — PD가 REVIEW 직전 게이트에서 돌린 출력
- 검증 기준 (prompts/draft-verify.md)
- 레퍼런스 분석 (_refs/*/analysis.md) — 독창성 검수 시 레퍼런스 고유 표현(비유·시그니처·펀치라인) 대조용

## 작업

prompts/script-review-checklist.md의 카테고리 검수 + 신규 주장 즉시 검증 + 독창성 검수로 검토:

### 1. 핵심약속 검수
- Hook에서 핵심약속을 바로 이행하는가
- 각 파트가 핵심약속 이행에 기여하는가
- 마무리에서 핵심약속이 완결되는가

### 2. 구조 검수
- outline.md 구조대로 작성되었는가
- 타겟 러닝타임 범위 내인가
- Hook/Intro가 hook-intro.md와 일치하는가
- 리텐션 장치가 배치되었는가
- verified-data.md 데이터만 사용했는가

### 3. 문체 검수

> 판정 기준은 `prompts/tone-guide.md`. 시청자는 **50~60대 이상 남성 시니어**다.
> 한 줄 판정법: **"이 문장, 술자리에서 친구한테 말로 하겠는가?"**
> **`check_tone.py` 출력 전문을 검수 보고서에 그대로 붙인다.** 항목을 생략하지 않는다.

- 쉼표/따옴표 남발 여부
- 쉬운 말 사용 여부
- 용어 순화 적용 여부 (tone-guide.md §2 치환표 대조)
- **숫자 처리 4원칙** — 반올림했는가 / 퍼센트를 '몇 중에 몇'으로 바꿨는가 / 던진 뒤 살림으로 착지했는가 / 한 문단 2개 이하인가
- **경제·행정 용어 과다 여부** — 공시·수주·순손실·시행령·조항·전략물자 등
- **개념 설명이 한 번에 그치지 않았는가** — 정의 → 일상 사물 → 생활 비유로 2~3번 다르게
- **1인칭이 분석 말투인가 감정인가** — "제가 이 숫자들을 나란히 붙여 놓고 본" 류는 위반. 8~12회 분산됐는가
- **검증 과정을 대본에 노출했는가** — "우리는 이 숫자를 안 씁니다", "표본이 약해서" 등
- **클로징이 통찰로만 끝나지 않았는가** — 마지막은 장면 + 감정이어야 한다
- **독재자 존칭 사용 여부** (치명적)
- **공포·클릭베이트 과장어 사용 여부** (개선 권장)

### 4. 톤 검수
- 채널 프로필 말투/톤 준수 여부
- outline.md 프로젝트별 톤 준수 여부

### 5. 신규 주장 식별
- draft.md의 모든 사실적 주장(비교, 수치, 구체적 사례)을 verified-data.md와 대조
- verified-data.md에 없는 주장을 신규 주장으로 식별

### 6. 신규 주장 즉시 검증
- 5단계에서 식별된 신규 주장 각각을 **WebSearch로 즉시 검증**
- prompts/draft-verify.md의 검증 기준을 적용
- 3단계 분류:
  - ✅ 검증됨 (오차 10% 이내)
  - ❌ 불일치 (사실과 다름)
  - ⚠️ 과장 (방향은 맞지만 과장/왜곡)

### 7. 독창성 검수

- `_refs/*/analysis.md`에 기록된 레퍼런스 고유 표현(비유·시그니처/캐치프레이즈·펀치라인·인상적 문구)을 대본과 대조한다.
- 사실·수치·사건의 중복은 위반이 아니다. **"표현"이 레퍼런스와 동일하거나 핵심 명사만 바꾼 수준이면 단 1개라도 치명적.**
- verified-data.md·outline.md에 레퍼런스에서 흘러든 비유가 있더라도, 대본이 그대로 옮겼으면 위반으로 본다.
- 위반 표현을 발견하면 정확히 인용하고, 어느 레퍼런스의 어떤 표현과 겹치는지 명시한 뒤 대체 표현을 제안한다.

### verdict 판단

- **치명적 1건 이상** → `verdict: 수정`
- **치명적 0건** → `verdict: 통과`

**⚠️ 주의**: 심각도 기준표의 분류를 절대 자의적으로 변경하지 않는다. 신규 주장 ❌/⚠️는 무조건 치명적이다. "문장 단위 수정으로 해결 가능"하더라도 치명적 분류를 유지한다.

**⚠️ 문체 항목 강등 금지 (2026-08-04 추가).** 숫자 밀도는 이전에 `개선 권장`이었다.
그래서 `changwon-german-acquisition` 검수는 기준 2.5배 초과를 **잡아내고도** "③ 문체 검수 — 조건부 통과"로 등급을 깎아
수정 목록에서 빼버렸고, `china-rice-cadmium`은 항목 자체를 보고서에서 누락한 채 `통과`가 나갔다.
두 대본 모두 사용자 검수에서 "재미없어서 끄고 싶었다"는 평가를 받았다.
**`check_tone.py`가 FAIL이면 다른 항목이 전부 통과여도 `verdict: 수정`이다. "조건부 통과"라는 판정은 쓰지 않는다.**

수정 시: 치명적 항목의 수정 지시를 구체적으로 명시 (어디를 어떻게). 개선 권장은 함께 전달하되 수정 필수는 아님.
통과 시: 개선 권장/사소 항목은 참고사항으로만 기록.

## 출력

`_script/review.md` — 아래 포맷:

```markdown
verdict: {통과 또는 수정}

## 0. 기계 검증 (check_tone.py)

(PD가 전달한 실행 결과 전문을 그대로 붙인다. 생략 금지)

## 체크리스트 결과
(5개 카테고리별 통과/지적사항)

## 심각도 분류

| 지적사항 | 심각도 | 판단 근거 |
|----------|--------|----------|
| {지적 1} | {치명적/개선 권장/사소} | {분류 이유} |

## 신규 주장 검증

없음

(또는)

| # | 주장 | 위치 | 검증 | 실제 | 수정제안 | 출처 |
|---|------|------|------|------|----------|------|
| 1 | ... | 파트 2 | ❌ | ... | ... | ... |

{수정 시: 치명적 항목별 구체적 수정 지시 (어디를 어떻게)}
{통과 시: 개선 권장/사소 항목 참고사항}
```

## 행동 규칙

- 객관적이고 구체적으로 지적. 모호한 피드백 금지.
- 지적 시 해당 문장/위치를 정확히 인용.
- 수정 제안은 실행 가능한 형태로 제시.
- verdict 판단에 주관적 해석 최소화. 심각도 기준표에 따라 기계적으로 분류.
- 신규 주장 검증 시 공식 통계(통계청, 협회, 감독원 등)를 우선 참조. 출처에 기관명 + 시점을 기록.

## 실행 방식

PD가 REVIEW_FINALIZE 단계에서 1개 에이전트로 호출.
